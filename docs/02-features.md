# 02. 機能設計

機能を 8 ブロック（A–H）に分解する。MVP は **A / C / D / E / F**。

| | ブロック | MVP | Phase 2 | Phase 3 |
|---|---|:---:|:---:|:---:|
| A | トピック管理 | ● | | |
| B | 週次リズム・フェーズ配分 | △ | ● | |
| C | 日次メニュー生成 | ● | | |
| D | 学習セッション（対話・ドリル・添削） | ● | | |
| E | 弱点リスト & 間隔反復 | ● | | |
| F | ログ・ストリーク・ダッシュボード | ● | | |
| G | リマインド通知 | △ | ● | |
| H | 複数人（アカウント・共有・グループ） | | ● | ● |

●＝作る／△＝最小構成だけ作る

---

## A. トピック管理

学習テーマ1つ＝1トピック。目標・マイルストーン・現在地を持つ。

- **A-1 トピック作成**：目標を自由記述で入力すると、AI がヒアリングして
  マイルストーン（M1…M5）と初回の「次の一手」を提案する。ユーザーは編集して確定
- **A-2 ステータス管理**：`active` / `paused` / `done`
  - 「◯◯は中断」→ paused（理由をメモに残す。ログは保持）
  - 「◯◯を再開」→ active に戻し、**空白期間を踏まえた現在地の再確認から始める**
  - 完了時は達成を明示的に祝う（done は最終状態）
- **A-3 マイルストーン**：チェックボックス。完了で進捗%を更新
- **A-4 定番メニュー**：トピックごとに「毎回の30分の組み立て」を定義できる
  （例：TOEIC＝ドリル15〜20分 + 英作文チェック10分）。メニュー生成の型として使われる
- **A-5 現在地メモ**：AI とユーザーの両方が更新できるフリーテキスト。メニュー生成の最重要入力

> 実運用での学び：`active` トピック数は 2 が上限。3 つ目を足すと週次配分が破綻する。
> UI 上も 3 つ目の追加時に警告を出す。

## B. 週次リズム・フェーズ配分

複数トピックを曜日に割り当てる。

- **B-1 フェーズ**：一定期間の配分パターン（例：フェーズ1＝AgentCore 厚め）。
  切替条件（例：「AgentCore の M2 完了時」）を持ち、**条件成立時に切替を提案**する
- **B-2 曜日割当**：月〜日 × トピックのマトリクス
- **B-3 デイリーミックス**：メインでないトピックも冒頭5分だけ混ぜるルール
  （語学は毎日接触が必要という原則）
- **B-4 週次復習日**：週1日を「その週の誤答＋弱点リスト再テスト」に固定できる

MVP では B-2 の固定表のみ。B-1 のフェーズ自動切替は Phase 2。

## C. 日次メニュー生成

**このサービスの心臓部。**

入力：
- 今日の曜日 → 週次リズム表
- active な各トピックの「現在地」「次の一手」「定番メニュー」
- 間隔反復キューの期限到来分（E-3）
- 直近の学習ログ（連続日数、直近のつまずき）

出力：合計30分の **タイムボックス付きメニュー**

```
今日（水）｜合計30分
┌ 5分  TOEIC 復習    昨日の弱点3型を再テスト（冠詞落ち・副詞語順・複合名詞）
├ 20分 AgentCore     Runtime の公式ドキュメントを読み、
│                    「なぜ Lambda でなく AgentCore か」を1段落で説明する
└ 5分  AgentCore     口頭試問：主要6コンポーネントの役割を言えるか
```

制約：
- **「勉強する」のような曖昧な項目を出力してはいけない**。必ず対象・方法・完了条件を含む
- 各項目は Ikkoma 内で完結できる形にする（AI が出題する／添削する／壁打ちする）
- ユーザーが「今日は別のをやりたい」と言えば即座に組み直す（メニューは提案であってノルマではない）

## D. 学習セッション

メニュー項目を実行する画面。AI との対話が主。

- **D-1 ドリル**：AI がその場で問題を生成・出題。1問ずつ解答→即時解説
  - 出題は弱点リストと現在のマイルストーンから重み付けされる
- **D-2 自由記述チェック（添削）**：ユーザーが作った文・説明を AI が添削
  - **弱点抽出はここが主戦場**。選択式より圧倒的に多くの型が取れる
  - 語学なら英作文、技術なら「自分の言葉で説明する」＝同じ仕組みで扱える
- **D-3 口頭試問**：AI が理解度を質問形式で確認する
- **D-4 読解の壁打ち**：ドキュメントを読んだ内容を投げると、AI が突っ込みを入れる
- **D-5 質問はいつでも**：セッション中の脱線質問も学習時間にカウントする
- **D-6 中断・再開**：30分の途中で抜けても状態が残る

## E. 弱点リスト & 間隔反復

**最大の差別化ポイント。**

- **E-1 型の自動抽出**：セッション終了時、誤答と添削差分から「ミスの型」を抽出する
  - 例：`× I am work` → 型「be動詞と一般動詞の併用」
  - 例：`× checked mail` → 型「冠詞の付け忘れ」（既存型に**再発**として紐付け）
  - 抽出結果はユーザーが承認／却下できる（AI の過剰抽出を防ぐ）
- **E-2 弱点リスト**：型ごとに 発生回数 / 初出日 / 最終再発日 / 習得状態 を持つ
  - **再発は強いシグナル**。回数が増えるほど出題重みが上がる
- **E-3 間隔反復キュー**：型ごとに次回出題日を持つ（1日→3日→7日→16日→35日、誤ればリセット）
  - 期限到来分が翌日のメニュー冒頭に自動で入る（C の入力になる）
- **E-4 卒業**：一定回数連続正解で `mastered`。リストから外れるが履歴は残る

## F. ログ・ストリーク・ダッシュボード

- **F-1 学習ログ**：日付・時間・トピック・内容。セッションから**自動生成**
- **F-2 ストリーク**：連続学習日数／最長／累計日数
  - 前日実施済みなら +1、空いたら 1 にリセット（最長は保持）
- **F-3 ヒートマップ**：GitHub 風の年間カレンダー
- **F-4 進捗**：トピック別のマイルストーン達成率と累計時間
- **F-5 週次サマリ**：今週やったこと・新規弱点・卒業した型を要約

## G. リマインド通知

- **G-1 昼（既定12:00）**：今日のメニューをプッシュ
- **G-2 夜（既定21:00）**：未実施なら再提示、実施済みなら称賛と翌日の一手
- **G-3 チャネル**：Web Push（MVP）→ LINE / Slack / メール（Phase 2）

## H. 複数人（Phase 2 以降）

- **H-1 アカウント**：メール／OAuth。全データを user_id で分離
- **H-2 テンプレート共有**：完走したトピック（目標＋マイルストーン＋定番メニュー）を
  テンプレートとして公開／複製できる。**中身のコンテンツではなく「進め方」を共有する**のがミソ
- **H-3 メンター共有**：特定ユーザーに閲覧権限を付与。ログと弱点リストが見える
- **H-4 グループストリーク**：数人でストリークを共有。誰かが落とすと全員に見える
- **H-5 週次レポート配信**：メンター／グループに週次サマリを自動送信

## MVP の完成条件

以下を1人（＝作者自身）が2週間continuously使えれば MVP 完成とみなす。

- [ ] 目標を入力するとマイルストーンが提案され、トピックが作れる
- [ ] 毎日ホームを開くと具体的な30分メニューが出ている
- [ ] メニューからセッションに入り、AI と対話してドリル・添削ができる
- [ ] セッションを終えるとログが自動で残り、ストリークが更新される
- [ ] 添削から弱点の型が抽出され、翌日以降のメニューに再出題される
- [ ] ダッシュボードでストリークとヒートマップが見える
