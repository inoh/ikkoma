# 03. ユーザーフロー

## F1. オンボーディング（初回のみ・目安5分）

```
[起動]
   ↓
[① 目標を入力]  自由記述 "TOEIC 600点を取りたい"
   ↓
[② AI ヒアリング]  3〜4問だけ
      ・現在地は?（受験歴／スコア／未受験）
      ・期限は?（任意）
      ・1日どのくらい?（既定30分）
   ↓
[③ マイルストーン提案]  M1〜M5 をAIが提示 → ユーザーが編集・確定
   ↓
[④ レベルチェック]  M1として実測（20問程度）
      ※「勘で当てた」申告を取る。当たった問題も未定着として扱う
   ↓
[⑤ 現在地の確定]  推定レベル＋弱点の初期リストを生成
   ↓
[⑥ 2つ目のトピック?]  スキップ可。追加した場合は週次リズムを提案
   ↓
[⑦ 通知時刻の設定]  昼/夜（既定 12:00 / 21:00）
   ↓
[Today 画面へ]
```

設計上の注意：
- ステップ④のレベルチェックは**飛ばせるが強く推奨する**。ここを飛ばすと
  以降のメニュー生成の精度が落ちる（現在地が不明なため）
- ステップ③でユーザーが編集した内容は、AI の提案より常に優先される

## F2. 日次ループ（毎日・30分）

```
[12:00 通知] ──→ [Today 画面]
                     │  今日のメニュー（タイムボックス付き）
                     │  ストリーク / 残り時間
                     ↓
              ┌── [組み直す?] ──→ AI に希望を伝えて再生成
              │        │
              ↓        ↓
           [セッション開始]
                     ↓
     ┌───────────────────────────────────┐
     │  項目1: 復習(5分)  弱点の再テスト   │
     │  項目2: ドリル(15分) AI が出題      │
     │  項目3: 添削(10分)  自作文をチェック │
     └───────────────────────────────────┘
                     ↓
              [セッション完了]
                     ↓
        ┌── 自動生成される ──────────────┐
        │  ・学習ログ1行                  │
        │  ・ストリーク +1                │
        │  ・新規/再発した弱点の型         │
        │  ・次回の一手                   │
        └────────────────────────────────┘
                     ↓
           [結果画面でユーザーが承認]
             （弱点の型は却下もできる）
                     ↓
              [間隔反復キューへ投入]
```

**離脱ポイントと対策**

| 離脱ポイント | 対策 |
|---|---|
| Today を開いたがメニューが重く感じる | 「今日は5分だけ」ボタン。ストリークは維持される |
| セッション途中で中断 | 状態を保持し、次回「途中から再開」を出す |
| 21:00 時点で未実施 | 夜の通知でメニューを再提示。ワンタップでセッションへ |
| 数日空いた | ストリークはリセットするが、**再開時は責めずに現在地の再確認から入る** |

## F3. 弱点ループ（Ikkoma の核心）

```
[セッション: 添削 or ドリル]
        ↓
  誤答 / 添削差分
        ↓
[AI が「ミスの型」に抽象化]
   × I am work        → 型: be動詞と一般動詞の併用
   × checked mail     → 型: 冠詞の付け忘れ（既存型に再発として加算）
        ↓
[ユーザーが承認 / 却下]
        ↓
   ┌─ 新規 → 弱点リストに追加、次回出題日 = +1日
   └─ 再発 → 発生回数 +1、次回出題日 = リセット(+1日)、出題重み↑
        ↓
[間隔反復キュー]  1日 → 3日 → 7日 → 16日 → 35日
        ↓
[期限到来分が翌日メニューの冒頭5分に自動投入]
        ↓
   ┌─ 正解 → 次の間隔へ。規定回数連続で mastered（卒業）
   └─ 誤答 → 間隔リセット、再発としてカウント
```

このループが F2 の「項目1: 復習(5分)」を毎日自動で埋める。
ユーザーは一度もカードを作らない。

## F4. トピックのライフサイクル

```
        [作成]
           ↓
      ┌─ active ─┐
      │     ↕    │
      │   paused │   ← 「◯◯は中断」/ 「◯◯を再開」
      │     ↕    │      ログ・弱点リストは保持
      └──────────┘
           ↓
         done      ← 全マイルストーン完了。達成を祝う
```

- `paused` にする時は理由をメモに残す（後で再開判断に使う）
- `paused` からの再開時は、空白期間の長さに応じて
  **現在地の再確認セッション**（軽い復習テスト）を挟む
- `done` になったトピックは、テンプレートとして公開できる（Phase 2 / H-2）

## F5. フェーズ切替（Phase 2）

```
[週次リズム: フェーズ1（AgentCore 厚め）]
        ↓
[切替条件を監視]  例: "AgentCore の M2 完了"
        ↓
[条件成立 → 通知]  「フェーズ2に切り替えますか?」
        ↓
   ┌─ 承認 → 曜日割当を差し替え
   └─ 却下 → 条件を再設定 or 現状維持
```
